# Web 视觉重构：把「对象」放回界面中心

> 目标不是“更花哨”，而是让老师/同学第一眼知道**这是什么、能点哪、为什么这样**。
> 参考：旧版 Web（`8765`，纸白 + 墨黑 + 衬线标题，无彩色编码）与 Memory Lens（对象优先、聚焦、多种 lens）。
> 预览：`web-preview/records.html`（用 conv-26 真实数据，静态版式，可直接打开）。

---

## 1. 现在的页面为什么“丑”

不是配色问题，是**信息顺序**问题。逐条对照：

| 现象 | 代码里的证据 | 后果 |
|---|---|---|
| 标题是机器 ID | `conv26_D1_7_f0`、`conv26_D1_7` | 用户不知道这条是什么 |
| 字段表像数据库 | `attribute / slot 属性`、`event time 事件时间`、`valid interval` | 像 debug 面板，不像产品 |
| 字符串拼接 | `Caroline · job = teacher · 事件：started new job` | “一堆字母数字连在一起” |
| 引用是代码 | `来源 D1:5` | 要猜 D1 是什么 |
| 指导文案堆在首屏 | 每页 2–3 行“数据来源/口径/不是 27B” | 用户先读免责声明，再找内容 |
| 图节点 9px mono | `.graph-node text{font-size:9px}`，label 截 34 字符 | 投影/笔记本上都看不清 |
| 状态靠颜色 | 绿/黄/红 pill | 与旧版“无彩色编码”的语言冲突，且色弱不友好 |

一句话：**页面在向用户展示数据库，而不是展示记忆。**

## 2. 两条参考各自给什么

**旧版 Web（老师说“舒适”）**
- 纸白 + 墨黑 + 一个灰阶；**状态用几何形状**（实心圆/空心圆/菱形），不用红绿；
- 衬线标题（Songti/Source Serif）+ 无衬线正文；15px 基准、1.75 行高；
- 内容宽度 1040–1180，四周留白 28–48px；`mono` 只用于引用编号。

**Memory Lens**
- **对象优先**：每条记忆先是一句话（谁、何时、发生了什么），结构化字段是附件；
- **聚焦 + 上下文**：图不做“毛球”，选中节点只展开 1–2 跳；
- **同一数据多种 lens**：关系网 / 时间轴 / 数据表，切换视角而不是堆功能；
- **详情即叙事**：时间、地点、正文、未结线索、原文摘录，而不是 key-value；
- **渐进披露**：schema 编辑、原始 JSON 都在二级入口。

## 3. 六条硬规则（照做就能“不丑”）

1. **对象优先**：每张卡片的第一行是「谁 + 什么事」，字段与 ID 一律靠后。
2. **ID 折叠**：`memory_id`、`turn_id`、`t_event` 只出现在「技术细节」里；对用户显示
   `D1:5 → 第 1 段 · 第 5 轮`。
3. **状态用形状，不用颜色**：● 有效 ／ ○ 历史 ／ ◇ 冲突 ／ ◌ 未解析。
4. **首屏只留一句说明**：口径、来源、限制放「系统」页或页脚一行，不放在内容上方。
5. **一个屏幕一个主对象**：列表是索引，右栏才是对象；不要让表格和说明同时抢注意力。
6. **聚焦而不是全铺**：图谱默认只显示选中实体的 1–2 跳；全图只做背景。

## 4. 文案对照（Before → After）

| Before | After |
|---|---|
| `conv26_D1_7_f0` | `Caroline · 心情` |
| `Caroline · job = teacher · 事件：started new job` | `Caroline 的爱好：painting`（卡片）；详情用完整句 |
| `attribute / slot 属性` | `类型` |
| `event time 事件时间` | `事件时间` |
| `valid interval` | `有效期`（技术细节里保留英文原名） |
| `来源 D1:5` | `来源 第 1 段 · 第 5 轮` |
| 首屏 3 行“数据来源/不是 27B/图为缓存” | 副标题一行：`conv-26 · 事实 335 · 事件 146`；口径移入系统页 |
| 图节点 `conv26_D1_7_f0` 9px | 实体名 ≥12px；ID 放 hover title |

## 5. 页面蓝图

### 记忆库（先改这一页，收益最大）

```text
左 220px      中 自适应                    右 430px
状态/类型/人物  记录卡片（谁 + 属性 + 值）    对象详情
              · 状态形状 + 时间 + 来源        · 衬线标题：Caroline · 心情
              · 2 行截断                    · 一句话（含时间）
                                           · 四个事实：事件时间/写入/来源/证据
                                           · 双时间两行（未知=虚线 + 说明）
                                           · 原文证据（引用块 + 出处）
                                           · 为什么失效（仅 HISTORICAL）
                                           · ▸ 技术细节（ID/JSON）
```

### 提问与状态

```text
问题输入（衬线大字）
→ 答案（衬线，18–20px）
→ 四个状态块：保留 / 更新 / 替代 / 冲突（各 1 行，冲突 0 时显示 0）
→ 引用证据（卡片，带出处）
→ ▸ 执行轨迹（trace，默认折叠）
```

### 图谱

```text
顶部两个 lens：关系 / 时间
画布：默认聚焦 1 个实体，1–2 跳；节点用实体名，不用 ID
右侧：选中节点的证据与关系（不弹窗）
边没有类型时不要着色，只画实线
```

### 评测

```text
首屏：一张主表（在线/离线分表）+ 一张图
实验计划矩阵移到 tab，不进首屏
```

## 6. 给 S1 的验收清单

- [ ] 记忆库首屏没有 `conv26_` / `D1:` 这类裸 ID；随机抽 5 条，人工能读懂是什么。
- [ ] 任一记录详情里，`memory_id` 只在「技术细节」出现。
- [ ] 状态筛选用形状 + 文字；不用红绿。
- [ ] 首屏说明 ≤1 行；口径/来源说明不在内容区。
- [ ] 图上节点标签 ≥12px，且是实体名不是 ID。
- [ ] 空数据（冲突 0）有明确文案，不出现空面板。
- [ ] 1440×900 和 1280×800 下不横向滚动。

## 7. 不要做的事

- 不要为了“高级感”加深色主题：旧版的白纸墨字是老师认可的语言。
- 不要把 05/01 那类海报图整张塞进页面（字会糊）。
- 不要给每种状态配颜色；形状已经够。
- 不要在内容区解释“这不是 27B 结果”；放到系统页/报告里。
