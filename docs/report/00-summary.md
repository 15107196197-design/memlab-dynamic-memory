# 报告摘要

本报告的主结论是：在线 27B 上，融合与校验能小幅提分，但没有一项结论达到可推广强度。这个判断不是对系统能力的否定，而是对证据强度的限定。本轮把六模块单因素、B0 与 R0 的 test 对照、检索命中到答案的转化率、retrieval oracle、2×2 组合以及重排对照放进同一套在线 27B 口径，数字都能回到报告 JSON。因此下文只给条件结论：哪些差异有区间支撑，哪些只是描述性观察，哪些因为接线或样本不足而不能解释。

先看方法边界。在线部分使用开发集四段对话与 test 两段对话，单因素主要是四十题、一个 seed，留出对照也只是八十题、两个 seed。它们足以比较同一 harness 内的候选排序，却不足以支撑“某模块在 test 上更好”的推广判断。offline 部分使用 hashing embedding 与抽取式回答，属于接口级验证，不能当作大模型答案质量的证据。报告反复标注这些口径，是为了避免把不同 harness 的数字拼成一个总分。

做对了什么。六模块单因素中，M1 的 RRF 融合 F1 为 0.3064，是六个模块里最高；U2 的 0.2998 紧随其后。检索命中后的答对率为 0.5657，比总体 0.5200 高 0.0457，说明检索对答案有正向作用。W2 为 0.1837，R2 为 0.1540，K3 的存储级更新正确率为 0.8086；M1 的代价是 403.83 tokens/题。除 M 与 U 外，其余模块的 F1 都与 W2 的 0.1837 接近，差距没有区间支撑，不能据此排出稳定名次。

没证明什么。B0 与 R0 的 F1 分别为 0.1883 与 0.1520，差为 −0.0363，95% 区间跨 0，只能算无定论；召回分别为 0.5435 与 0.3403，差为 −0.2032，区间不含 0，是唯一确定的负向结论。R0 更省更快，但代价是确定的召回损失，因此不能写成 R0 更好。三种图表示结果完全相同，属接口未接线，不能读成“无差异”。图检索的最终召回为 0.2372，仅比纯向量的 0.2257 高 0.0115；图通道能产出 34 到 91 条候选，但融合后 0 条存活，瓶颈在融合预算。重排把 nDCG 从 0.4315 提高到 0.5123，同时把召回从 0.5785 压低到 0.3498、F1 从 0.2844 压低到 0.2373，是排序质量与证据覆盖的交换，不是全面胜利。

与归档基线的关系也要说清。上一版 27B 归档在 test 120 题上给出 Full 0.5589、Vector 0.3623、Hybrid 0.3986、Dynamic 0.4157；本轮 B0 为 0.1883、R0 为 0.1520。两者题集、答案器与评测口径都不同，只能当参照，不能据此说系统退步。真正可比的是同一轮内的 B0 与 R0 对照，以及同一 harness 下的单因素排序。把这两类数字混在一起，就会得到“全文永远最好”或“动态方法已经胜出”这类无法复核的结论。

组合层的收益同样很薄。E3 的 2×2 中，加权融合加直接作答为 0.1764，高于单通道的 0.1500；但证据链没有同步变好，说明融合带来的主要是排序层面的改善。所有在线实验都仍缺 LLM Judge、第二 seed 和配对的状态准确率，四十题、单 seed 的结果只能作方向性参考；十七题的状态基准也不足以替代在线状态评测。因此“融合有用”目前只能写成有限条件下的描述，不能写成稳定增益。

下一步先补第二 seed、LLM Judge 和按对话的 cluster bootstrap，再修图检索接线与 cross-encoder 回退。在这些完成之前，任何“某模块更好”的说法都只按描述性结论使用，不升级为可推广结论；offline 的负结果也不能直接当作架构判决。报告保留这些边界，是为了让每个数字都能被复核，而不是为了给出一个好看的总分。也只有把失败模式、接线状态与样本量一起写出来，后续工作才知道应该先修哪一段链路。
